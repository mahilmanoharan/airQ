# Code review, round 2 (2026-09-28)

A `/code-review high` pass returned 10 unverified findings. Each was checked against the code; all were real and are fixed:
1. **Route change/interruption lost windows**: the handlers closed the events stream before `pipeline.finish()` flushed. They now call `stop(finishingWith:)`, and `AnalysisPipeline.finish(throwing:)` ends the stream with the reason *after* the flush. The test asserts an error-finish yields exactly the same window count as a normal finish.
2. **Pollen 429/5xx blocked retries for the day**: `DashboardViewModel.isSettledForToday`. Only 2xx and non-429 4xx settle the day.
3. **Pollen day keying**: Google's forecast dates are UTC-based. `PollenReading.firstDayKey`/`dayKeys`/`overallIndex(forDayKey:)` (`DayKey` helpers) now key the widget's tomorrow line and the card's outlook labels. The card notes when day 0 isn't local today.
4. **Provider gaps re-downloaded 696 h daily**: `RecordStore.settledHourStarts` counts hours inside a successful page's returned span as settled. A final page (no `nextPageToken` in the stored raw body) settles back to its requested start. The collector closure is now `settledHours`.
5. **Offline attempts counted as usage**: new status `notSent` (`HTTPAirQualityClient.neverSentCodes`), not counted by the budget or `latestRequestAt`.
6. **Export paging ties**: every paged export sort ends with `SortDescriptor(\.id)`. Regression test: 1,200 identical hours export exactly once each.
7. **Chips with symptoms = no**: "No" clears chips, and the store rejects the contradiction (`symptomsWithoutDaytimeSymptoms`).
8. **48 h card staleness**: `EnvironmentRecorder.revision` → `\.environmentRevision` is the card's reload key, so it reloads after each saved attempt, including history pages.
9–10. Diagnostics fetch only `hourStart`/`observationID`; Trends overlaps detection-store reads with `async let`.

**Test-infrastructure finding**: SwiftData caches one class per entity name per process. Inserting `SchemaV2.DailyCheckIn` while V3 `DailyCheckIn` objects exist (parallel tests) crashes with `NSUnknownKeyException … controllerAdherence`. The app never creates V2 objects, so this is test-only. The V2→V3 test therefore migrates a committed fixture, `RespiratoryKitTests/Fixtures/SchemaV2Store` (regenerate it alone: `WRITE_V2_FIXTURE=<dir> swift test --filter writeV2Fixture`). Also: a `ModelContext` doesn't retain its container, so always keep the container in a variable.

# Code review, round 5 (2026-09-29)

# Decision made: "Erase all data" (2026-09-29, architect's call; the user delegated it)

Built as a deliberate, narrow exception to "append-only, never delete": `EraseDataView` (route `.erase`, in the Health tools menu, listed on About) lists exactly what goes, offers "Export a copy first", and needs a confirmation dialog. `DataEraser` → `RespiratoryStore.eraseAll` (batch-deletes every model in `SchemaV3.models`, off the main actor) + clears the App Group snapshot/place, tuning, mic-consent acknowledgment, last-export time, and `tmp/Exports`; reloads widgets; adds today's day row. **Kept**: alert and export preferences. The deleted bytes can linger in SQLite free pages, so `eraseAll` also sets `airQErasePending`, and the next `openContainer()` removes the store files (`-wal`, `-shm`, `.default_SUPPORT` too) **only if no user-authored rows (sessions, windows, legacy events, annotations, check-ins, context events) exist** — provider attempts/days/history don't count, since using the app recreates them; if the check can't run, nothing is touched. Side effects to know: the Google history backfill (≤ 5 requests) and the app-side usage counts restart after a purge (Cloud Console quotas remain the real guard). UI tests use an in-memory store and a throwaway defaults suite, so they never touch real state. Tests: 4 package tests on real on-disk stores (all tables emptied and reusable, files + external blobs purged, newer user data protected, no flag = no purge) and 1 UI test (cancel path, confirm path). **Verified end to end on the iPad scratch sim** (DEBUG `-autoErase YES` runs the erase from the screen): the store file's inode changed exactly at the next launch, the flag cleared, a new store's earliest row was after the purge, and the history backfill re-fetched 696 hours (5 requests) as predicted. Not verified on a phone with real data.
